# 机制参数语义与市场贴近性（B 类参数审查）

> 目的：检查 `CapstoneScenario` 中**机制运行参数**的默认值是否具备学术意义，
> 以及如何贴近真实市场而非"拍脑门"。区分三类：
> (a) **学术定义明确**（来自规范公式/机制设计），
> (b) **需市场校准**（应来自数据/协议观测，当前是占位默认），
> (c) **检测阈值**（经验值，需在 MNIST 上实证）。

---

## 一、审计市场 / BFT 参数

| 参数 | 默认值 | 学术定义（规范 §18–§20） | 市场贴近性 / 建议来源 |
|---|---|---|---|
| `f`（Byzantine 容错） | 2 | 诚实节点数须 > 2f，m=3f+1, q=2f+1（§20） | 由协议对审计市场诚实比例的**观测/认证**决定，非拍脑门 |
| `m=3f+1, q=2f+1` | 7 / 5 | 推导自 BFT 安全/活性下界（Lamport/§20） | **学术固定**，非参数 |
| `eta_b`（Byzantine 比例） | 0.0 | `P_safe = P(K_B ≤ f), K_B~Binomial(m,η_B)`（§20） | 应来自历史恶意节点观测；`0` 表示"假设无恶意"，最乐观 |
| `eta_o`（offline 比例） | 0.0 | `p_H=(1-η_B)(1-η_O)`, `P_live`（§20） | 应来自节点在线率观测；`0` 最乐观 |
| `rho`（challenge 率） | 0.0 | `ρ p_v λ_A B ≥ G^dev+ε`（§19 stake 约束） | 应来自 `minimum_auditor_stake` 反推；`0` 表示不挑战 |
| `min_stake` | 0.0 | `B_{A,i}^min=(G^dev+ε)/(ρ p_v λ_A)`（§19） | 应来自 slashing 约束；`0` 表示无质押要求 |

**学术意义**：这些不是拍脑门——`f/m/q` 是 BFT 安全下界的**定理**，`η_B/η_O/ρ` 进入 `p_safe`/`p_live`/`minimum_auditor_stake` 的**概率公式**。但默认值 `0` 是最乐观假设，**不贴近真实市场**（真实审计市场必有离线/恶意节点）。

**贴近市场**：应通过协议观测注入真实 `η_B`（历史恶意率）、`η_O`（在线率）、`ρ`（由 stake 约束解出）。当前 `0` 是"理想化基线"，用于证明机制正确性。

## 二、检测认证参数

| 参数 | 默认值 | 学术定义 | 市场贴近性 |
|---|---|---|---|
| `a_D, b_D` | 1.0, 1.0 | `p̲_B^sys=Q_{α_D}[Beta(a_D+TP,b_D+FN)]`（§22）Beta 先验 | 无信息先验（Uniform）；有历史时应用历史 posterior |
| `alpha_D` | 0.05 | 下界置信分位数（§22） | 合同约定的置信水平，如 95% |
| `tp, fn` | 12, 2 | 认证运行的真实检测样本（§22/§67） | **应由受控 breach injection 实证得到**（P6 已实现，不再手填） |

**学术意义**：Beta-Binomial 后验下界是**贝叶斯统计**的标准结果。`alpha_D` 是统计显著性水平。

**贴近市场**：P6 已把 `tp/fn` 从手填改为真实注入检测。`alpha_D=0.05` 是行业惯例（95% 置信），可接受。

## 三、责任 / 定价参数（§30–§41）

| 参数 | 默认值 | 学术定义 | 市场贴近性 |
|---|---|---|---|
| `g_dev`（偏离收益） | 60 | 卖方 IC：`p̲_B^sys(p_{e,Bond}λ_S B+p_{e,F}F) ≥ G^dev+ε`（§30） | 应来自卖方偏离的**收益估计**（市场分析） |
| `eps_s` | 1.0 | IC 松弛 ε（§30） | 数值容差 |
| `p_e_bond` | 1.0 | bond 自动执行概率（§30） | 链上自动执行=1；链下需估计 |
| `p_e_f` | 0.3 | 链下额外处罚执行概率（§30） | 法律/声誉执行概率估计 |
| `lambda_s` | 0.5 | slash fraction（§30） | 合同约定的罚没比例 |
| `f_s` | 10 | 链下额外处罚额（§30） | 合同金额 |
| `kappa_s` | 0.1 | 资本占用费率（§31） | **市场利率**（如 10%/年） |
| `t_pre, t_post` | 1.0 | 保证金时间区间（§31） | 交易时长（年） |
| `beta_bar` | 0.5 | `P*=P_min+β_bar·M_T`（§41） | **谈判力系数**；0.5=均分剩余 |

**学术意义**：全部来自**激励相容（IC）约束**与**定价公式**（§30/§31/§38–§41），是博弈论/机制设计的标准结构。`B_S^*`、`P_max`、`P_min` 由这些参数**推导**。

**贴近市场**：
- `kappa_s` 应=真实资本成本率（如央行利率+风险溢价），非拍脑门。
- `p_e_f`（链下执行概率）应来自法律/声誉机制的现实估计（0~1）。
- `beta_bar` 反映买卖双方谈判力，应由市场结构决定。
- 这些是**合同/市场输入**，代码不臆造——但默认值需在实验说明中标注为"设定值"。

## 四、真实证据源检测阈值（C 类新增）

| 参数 | 默认值 | 学术定义 | 市场贴近性 |
|---|---|---|---|
| `alpha_shift` | 0.01 | KS 检验显著性水平（§11） | 统计显著性，行业惯例（1%） |
| `label_error_threshold` | 0.28 | CL label 误差率阈值 | **经验值**，应在 MNIST 干净数据上标定 |
| `dup_threshold` | 0.05 | 整行重复率阈值 | **经验值**，应在数据上标定 |
| `node_primitives` | ks/CL/dup 混合 | 节点独立 primitive | 审计市场能力集 |

**学术意义**：`alpha_shift` 是假设检验显著性；CL label error 是 Confident Learning 的 `estimated_label_error_rate`（§10）。

**贴近市场**：`label_error_threshold`/`dup_threshold` 是**经验阈值**，应在干净数据上测量基线（如 MNIST 干净 label_error≈0.16）再加容差得到。已在 `scripts/audit_effectiveness.py` 实证（干净 0.16→污染 0.38）。

---

## 五、结论与建议

1. **学术意义**：所有 B 类参数都有明确的学术来源（BFT 安全下界、Beta-Bayesian 后验、IC 激励约束、定价公式、KS/CL 统计），**不是拍脑门**。
2. **默认值**：多数是"理想化/合同设定"值。`η_B=0, η_O=0, rho=0` 是最乐观基线；`kappa_s, p_e_f, beta_bar, g_dev` 是合同/市场输入。
3. **市场贴近性**：
   - **应从协议观测/数据校准**：`η_B`（恶意率）、`η_O`（离线率）、`alpha_shift`、检测阈值 → 已部分实现（真实证据源）。
   - **应从市场/合同确定**：`kappa_s`（资本成本）、`p_e_f`（链下执行概率）、`beta_bar`（谈判力）、`g_dev`（偏离收益）、`p_e_bond`（执行概率）。
   - **应由受控注入实证**：`tp/fn` → 已由 P6 真实实现。
4. **建议**：正式论文实验应在场景 JSON 中显式给出全部市场参数，并注明来源（协议观测/合同/市场数据），而非依赖默认值。
